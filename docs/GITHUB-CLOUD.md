# GitHub and cloud setup: laptop can be switched off

GitHub stores the source and runs APK builds. A cloud web service runs the real-time music server. GitHub Pages serves static sites, so it cannot execute this app's Node.js/WebSocket backend. GitHub Actions builds/tests the project; it is not the continuous music server.

## Repository

The project is uploaded to the public repository [moses-code-master/CarSyncMusic](https://github.com/moses-code-master/CarSyncMusic), with the user's explicit permission to make its source public. The folders `backend`, `android`, `render.yaml`, and `.github` are directly at the repository root. Do not upload build folders, node_modules, local.properties, tokens or personal MP3s. The provided `.gitignore` covers generated app/server files.

The `.github/workflows/build.yml` workflow runs backend tests and builds the Android APK on pushes to main, pull requests and manual runs. [The verified GitHub build](https://github.com/moses-code-master/CarSyncMusic/actions/runs/38573596239) passed both jobs and uploaded the APK. Open the run → Artifacts → CarSyncMusic-debug-apk. Extract the APK before copying it to each car. The workflow installs Android SDK tools explicitly.

Artifacts use a development signing key generated by each fresh runner. APKs from different workflow runs may need uninstall/reinstall, which clears the app's session and library grants. For stable updates/public distribution, configure a private release keystore through GitHub Actions secrets and sign releases; never commit a keystore or its password. Actions usage/storage may incur charges depending on your GitHub plan and usage.

## Free cloud server selected for this project

The service `carsync-music` is deployed on Render's `free` plan in Frankfurt, without a paid disk, at `https://carsync-music.onrender.com`. The root `render.yaml` matches this configuration. Its filesystem is temporary: SQLite sessions and permitted MP3 uploads can be lost on restart/deploy. Free services can sleep after inactivity. No paid compute plan or paid disk was selected.

For this existing deployment, enter the server address above in both cars and use the release APK. The steps below are for reproducing the deployment in a different account; do not create a duplicate service in the existing account.

1. Sign in to [Render](https://dashboard.render.com/) and authorize access to this repository.
2. Choose New → Blueprint and select the repository, branch `main`, Blueprint path `render.yaml`.
3. Confirm the service plan is Free and no paid disk or paid resource is being added.
4. Wait for a healthy service. Render provides a public HTTPS address; no purchased domain is required for the default address.
5. Open `https://YOUR-SERVICE.onrender.com/health`; expect `{"ok":true}`.
6. Enter that same HTTPS root URL in Settings on both cars. Create/join a new session and use the included test MP3s to validate real playback.

Render terminates HTTPS and proxies WebSockets. Use its provided PORT environment variable; the backend already reads it and listens on all interfaces. Caddy/Docker Compose are for independent VPS deployment and are not used by this Render deployment. Keep one service instance because this app uses SQLite and in-process WebSocket sessions. Cloud deployments/restarts disconnect sockets; Android reconnects, and a backend restart restores the session paused.

Your laptop is no longer needed to serve music sessions. Both cars need connectivity to this public server, whether they use Wi-Fi or mobile data. Uploaded permitted MP3s reside on the cloud service's temporary filesystem; matching local MP3s require only small synchronization messages. Sessions still expire after 24 hours by design.

## Trial limitations

Import identical local files on both devices, expect to recreate sessions after a cloud restart, and do not depend on this trial for reliable road trips. Free-service quotas and policies may change. The equivalent `deploy/render-free.yaml` is also available. A future reliable deployment would need always-on hosting with persistent storage, but no paid configuration is selected for this request.
